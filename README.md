# MeteoTrace

Исследовательская веб‑платформа для просмотра спутниковых метеоданных, сравнения временных кадров и сохранения воспроизводимых кейсов. Это не официальный прогноз погоды и не система предупреждений.

- Production: https://meteotrace.vercel.app
- GitHub: https://github.com/rhys2313/MeteoTrace

## Что реализовано

- карта OpenLayers с поиском города/координат, выбором точки, областью, геолокацией, масштабом, полноэкранным режимом и прозрачностью слоя;
- защищённый серверный прокси к официальному EUMETView WMS: фиксированный endpoint, allowlist слоёв и CRS, проверка BBOX/размера/времени, timeout и понятный `503` без подмены снимка;
- серверный Copernicus OAuth readiness‑check, не передающий секреты в браузер;
- временная шкала, управление воспроизведением и пять режимов A/B: вертикальный, горизонтальный, прозрачность, мигание и визуальная разность;
- граф происхождения исследования, сохранение кейсов в `localStorage`, импорт JSON, дублирование, hash‑ссылка, экспорт TXT/JSON/PNG‑карточки/PDF;
- строгий TypeScript, ESLint и Vitest.

## Данные и ограничения

EUMETSAT используется через `https://view.eumetsat.int/geoserver/wms`. Перед созданием WMS‑слоя приложение запрашивает `GetCapabilities`; при отказе источника слой не создаётся и интерфейс показывает `WMS недоступен`, а не синтетическое изображение.

Локальная сеть разработки не смогла установить TLS‑соединение с EUMETView, поэтому живой снимок здесь не был подтверждён. Сам маршрут и клиентский слой готовы к проверке в Vercel/другой сети с доступом к endpoint.

Временные слоты до получения live extent служат навигацией запросов; они не являются утверждением о наличии снимков. Выводы платформы ограничены техническими различиями отображаемых пикселей и не интерпретируются как диагноз атмосферных явлений.

## Copernicus Data Space Ecosystem

1. Создайте OAuth client в Copernicus Data Space Ecosystem.
2. Скопируйте `.env.example` в `.env` и задайте `COPERNICUS_CLIENT_ID` и `COPERNICUS_CLIENT_SECRET`.
3. Для Vercel добавьте те же значения как encrypted environment variables для Production.

Секрет остаётся только в Route Handler `/api/copernicus` и не начинается с `NEXT_PUBLIC_`.

## Проверки

`npm run test` покрывает разбор координат, импорт/миграцию кейсов, статистику разности пикселей и валидацию WMS proxy. Ручная browser‑проверка включает загрузку приложения, недоступный WMS без ошибки декодирования, Copernicus credentials state и режим «Разность».
